Workbench vs Jira, side by side

I walked the same battery-pack project through both apps on 2026-11-24, at the same 1366 px window. Workbench ran on latest main (#42) with the fake backend: 4 epics, 11 tasks, 3 subtasks, dates and dependencies. Jira was the Car 6 Battery Pack space from the earlier run. These are proposals only. Nothing changes until you approve each one.

How to read this

  • W1–W9 are new proposals, in priority order. Each one names what Workbench does now, what Jira does, and what I'd change.
  • The item page and workflow editor gaps are left out, because they're already being built in another session (edit in place, status dropdown, Jira-style layout, shortcuts, per-type workflows, simpler editor).
  • At the end: where Workbench is already ahead of Jira and should stay as it is.

W1

Open items on top of the page you're on

HighVisual + behavior

Now

Clicking a card on the Board (or a row on the List) leaves the board for the full item page. To get back you use the browser's Back button, and the board redraws from the top.

Jira

The item opens in a large panel over the board. The address becomes ?selectedIssue=KAN-8, so the link can be shared. Esc closes it and you're where you were, with the card still highlighted.

Proposed

Board, List, Backlog, Timeline and Calendar open an item in the same peek panel Requests and Inventory got in #37. It shows the whole item page, including edit in place once that lands, plus "Open full page ↗". Esc or ✕ closes it. The link becomes …/board?item=BAT-8.

Files

views/projects/board.js, list.js, backlog.js, calendar.js, timeline.js, item.js (render into a given element), the shared peek from #37. It should land after the item-page PR, since both touch item.js.
W2

Leaner board cards; epics off the board by default

HighVisual

Now

A card is about 130 px tall. It repeats the column's status as a chip ("Draft" in the Draft column), shows a "–" bubble when nothing is set, and puts the key in small print above the title. Epics sit on the board as cards beside their own tasks: 2 of the 11 Draft cards and 2 of the 4 In Design cards are epics.

Jira

Cards are about 90–110 px: the title first, then the date and the epic as a chip, then a footer with the type icon, the key, a priority icon and an avatar. There's no status chip, because the column says it. Epics aren't on the board; they show as the chip on each card.

Proposed

Title first. One middle line with the due date, parent chip and checklist count. A footer with type icon + key, priority as an icon (only when High or Low), and an avatar. Drop the status chip and the "–" bubble. Hide top-level items (epics) from the board unless "Show epics" is ticked in Columns & cards.

Files

views/projects/board.js (card markup, board setting), css/projects.css. No database change: the setting goes in the board's saved settings.
W3

Fix: the Engineering design template puts every field on every type

HighBug

Now

In a new project from Engineering design, all six template fields have no types set: Requirement, Analysis type, Review date, Test procedure, Measured result, Outcome. So a Design Task's New item form asks for a test procedure and a review date. That's a big part of why the form is so tall.

Jira

In a team-managed space, a field belongs to the work type it was added to.

Proposed

In the template:
  • Test procedure, Measured result and Outcome go on Test.
  • Analysis type goes on Analysis.
  • Review date goes on Design Review.
  • Requirement goes on Epic and Design Task.
Existing projects aren't changed automatically. Settings → All fields already lets a lead set this per field.

Files

The template data (a migration that updates pm_templates, the next free number, which pairs well with the per-type workflows PR that also edits this template), tests/projectsStage2.test.mjs.
W4

A short New item form with "Create another"

HighVisual

Now

New item is an 818 px dialog: Kind, Title, a Description box, Owner / Priority / Due date / Parent, then a "More" section with every custom field. After Create it closes, so adding five items means opening it five times.

Jira

A compact dialog with project and type at the top, a big title, a description line, then one row of chips: Subsystem, Assignee (Automatic), Parent, Priority, Labels. There's a "Create another" tick box next to Create.

Proposed

Kind + Title at the top, then a one-line description that grows as you type. Owner, Priority, Due and Parent become a row of small pickers with their current value shown. Required custom fields stay visible; optional ones go under "More fields (n)". A "Create another" tick box keeps the dialog open with Kind and Parent kept.

Files

views/projects/kit.js (createItemDialog, formSections), css/projects.css. Forms set up in Settings still decide which fields are required.
W5

List as a tree

MediumVisual

Now

The List is flat, in backlog order: four epics first, then tasks, then subtasks at the bottom with a ↳. To see what's under BMS you read the parent chips row by row.

Jira

The List starts with the top-level items, each with a ▸ to fold it open. Children are indented under their parent. Footer: "+ Create" and "7 of 7".

Proposed

A "Tree / Flat" switch in the List's ⋯ menu, with Tree as the default. In Tree, epics show ▸ / ▾, children sit indented under them, and the open/closed state is remembered on this device. Sorting or a filter that hides a parent switches to Flat for that view and says so.

Files

views/projects/list.js, css/projects.css. Saved views keep the setting.
W6

Summary opens with four clickable 7-day numbers

MediumVisual

Now

The first card is "How it's going": a bar, six counts, and three boxes with explanations in small print ("Estimated hours finished ÷ all estimated hours (6 items have no estimate…)"). The 7-day numbers are a line inside Coming up. Orders & budget and Share with alumni take full cards even when they're empty.

Jira

Four tiles across the top: completed, updated, created, due soon (with "in the last 7 days" / "in the next 7 days"). Each tile opens the list filtered to those items. Charts come below.

Proposed

  • A row of four tiles at the top: Finished, Changed, Added, Due soon. Each opens the List with that filter.
  • The three-ways progress keeps its numbers; its explanations move behind the ⓘ that's already there.
  • Orders & budget and Share with alumni shrink to one line each when there's nothing in them.

Files

views/projects/project.js, css/projects.css. It uses the ready-made searches from #35 for the links.
W7

Grey placeholder rows while a page loads

MediumVisual

Now

While a Workbench page fetches its data, the area under the top bar is blank. It looked broken for a few seconds more than once during this run.

Jira

Every view first draws grey placeholder shapes in the layout it's about to show (rows, bars, a donut), so you know it's coming and where things will be.

Proposed

One small shared helper that draws a few grey placeholder rows or cards matching the view (list rows, board columns, timeline rows). It's shown only if loading takes more than about 200 ms, so quick loads don't flicker.

Files

views/projects/kit.js (helper), the Workbench router hook, css/projects.css. Reduced-motion users get no shimmer.
W8

Timeline: Status and Owner columns, progress on parent bars

LowVisual

Now

The work column shows only names. Epic bars are an outline with no sense of how far along they are.

Jira

The left table can show Status (for an epic, a done / in progress / to do bar) and Assignee.

Proposed

Two optional columns under Show: Status and Owner, both off by default. A parent's bar fills in from the left by the share of its children that are done.

Files

views/projects/timeline.js, css/projects.css.
W9

Switch projects from the project name

LowVisual

Now

To go to another project you go to Projects, then pick it.

Jira

A left sidebar lists starred and recent spaces on every page.

Proposed

No sidebar, since that would be a redesign. Instead the project name in the header gets a small ▾ with your recent projects and "All projects", and the current tab is kept (Board → the other project's Board).

Files

views/projects/kit.js (header), recent list in localStorage.
Keep

Where Workbench is already ahead

  • Timeline: dependency arrows, critical path, phases, car cycles, Fit and Present. Jira's opens with the epics folded and a mostly empty chart.
  • Board columns: a saved mapping. Jira appended new statuses after Done in creation order.
  • Moves: approvals, required fields and roles are checked by the database. Jira Software has no approval step.
  • Undo on edits and deletes; Jira has none.
  • Links to Orders, Inventory, Events and Sponsors with live status.
  • My work shows blocked items with the reason.
  • Rules with Try it and a run log, plus the starter templates.
